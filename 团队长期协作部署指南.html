一、先弄清楚：这套白板到底需要什么

这套白板没有后端数据库，整个系统只有两样东西：

组成 是什么 部署在哪
whiteboard.html 白板页面本身（单个 HTML 文件，约 265KB） 服务器上，由中继顺带托管
relay-server.js 中继：把一个人的操作转发给其他人，并把房间内容存成 json 服务器上，一个 Node.js 进程
rooms/ 目录 每个房间一份完整快照 服务器磁盘

运行原理，一句话：所有人的浏览器都连到你这台服务器，改动由服务器转发；同时每人浏览器里也留一份本地存档（断网还能看、能改，恢复后自动同步）。

3–5 人的资源消耗参考：

指标 实际占用 说明
内存 50–150 MB 1GB 内存的机器都够，2GB 更宽裕
带宽 平时几乎为 0；贴图/拖动时几 Mbps 4M 峰值够用，30M 更稳（跨境尤其）
磁盘 几十 MB 起 图片多的板子会涨，注意 --snapmb 上限
并发 3–5 人 默认上限 500 连接，完全用不到

你不需要买的东西：数据库、云存储、CDN、负载均衡、付费证书、短信服务。域名和 HTTPS 是"可选加分项"，不买也能用。

三、方案 A：阿里云香港轻量（推荐路径）

3.1 购买（约 10 分钟）

  1. 打开 https://www.aliyun.com，注册账号并完成实名认证（个人支付宝扫脸即可，境外节点同样要求实名）。
  2. 进入「产品 → 轻量应用服务器」，点「立即购买」。
  3. 地域选 中国香港。
  4. 镜像选 系统镜像 → Ubuntu 24.04（不要选 WordPress、宝塔等应用镜像，避免多装一堆用不到的东西）。
  5. 套餐选 2核2G（60GB ESSD / 30Mbps / 2048GB/月）；购买时长选 3 年（若只想先试，选 1 年）。
  6. 勾选自动续费提醒（不必开自动扣款），下单支付。
  7. 支付完成后在「轻量应用服务器 → 服务器」里能看到实例，记下公网 IP。

3.2 放行端口（最容易漏的一步）

在实例详情页找到「防火墙」（有的界面叫安全组），添加规则：

应用类型 协议 端口 备注
自定义 TCP 8787 白板必需
自定义 TCP 80 以后绑域名、签证书用
自定义 TCP 443 以后上 HTTPS 用

只放 8787 也能正常用；80/443 是给第五节的 HTTPS 预留的。这一步没做，浏览器会一直转圈打不开。

3.3 登录服务器

两种方式，任选：

  • 方式一（推荐给新手）：实例详情页点「远程连接」→ 按提示设置/输入 root 密码 → 网页里直接出现黑色终端窗口。
  • 方式二（Windows 10/11）：按 Win + X 打开「终端」，输入 ssh root@你的公网IP，首次会问 yes/no，输 yes，再输入密码（输入时屏幕不显示，属正常）。

登录成功后，提示符类似 root@iZxxxx:~#。

3.4 一键部署（复制粘贴即可）

依次粘贴执行（把 你的口令 换成一串 12 位以上的随机字符，例如 wb-7Kp2mQ9xT4vR）：

sudo -i
curl -fsSL -o deploy.sh https://raw.githubusercontent.com/rkdehd-rgb/whiteboard/master/deploy.sh
bash deploy.sh --token 你的口令

脚本会做五件事：装 Node.js（若缺）→ 建 /opt/whiteboard → 拷贝程序 → 注册 whiteboard 服务并开机自启 → 打印可分享的网址。

看到类似下面的输出就成功了：

==> 部署完成

  服务器公网 IP：47.xx.xx.xx
  健康检查：    http://47.xx.xx.xx:8787/health?token=你的口令
  打开白板：    http://47.xx.xx.xx:8787/?token=你的口令
  发给同事：    http://47.xx.xx.xx:8787/?token=你的口令#room=team

如果 curl 下载失败（GitHub 在国内时常抽风），改用手工上传，效果一样：

  1. 在你自己的电脑上，把 whiteboard.html、relay-server.js、deploy.sh 三个文件放到同一个文件夹；
  2. 在该文件夹打开「终端 / PowerShell」，执行（把 IP 换成你的）：
    bash scp whiteboard.html relay-server.js deploy.sh root@你的公网IP:/root/
  3. SSH 登录服务器，执行：
    bash sudo -i bash /root/deploy.sh --token 你的口令

3.5 验证

  1. 浏览器打开 http://你的IP:8787/health?token=你的口令，应看到一段 JSON：
    json {"ok":true,"auth":true,"rooms":[],"snaps":[],"limits":{"conns":500,"msgPerSec":120,"snapRooms":200}}
    ok:true 说明服务活着；auth:true 说明口令已生效。
  2. 打开 http://你的IP:8787/?token=你的口令，进入白板。右上角「协作」按钮旁的小圆点变成蓝色，即为实时通道已接通；灰色说明没连上（见第九节）。

3.6 发给同事

链接格式（顺序不能变：先 ?token=，再 #room=）：

http://你的IP:8787/?token=你的口令#room=proj-a

房间号规则（重要）：

  • 只能使用 字母、数字、下划线 _、点 .、短横 -，长度 1–64；
  • 不要用中文。中继只认 ASCII 房间名，中文会被并到公共房间，导致不同项目的内容混在一起；
  • 建议用小写拼音或英文项目代号：#room=pan-tu、#room=weekly。

不带 #room= 打开时，会自动进入「公共白板」（房间 main）。第一次使用时内容里会有一点示例便签，清空即可。

3.7 手动部署（脚本不适用时）

点开查看完整手工步骤（Ubuntu / Debian） 
# 1. 装 Node.js 18+（Ubuntu 24.04 自带 18，可直接 apt 安装）
apt-get update && apt-get install -y nodejs
node -v          # 应显示 v18 及以上

# 2. 建目录并放程序（假设已上传到 /root）
mkdir -p /opt/whiteboard/rooms
cp /root/relay-server.js /root/whiteboard.html /opt/whiteboard/
useradd --system --home /opt/whiteboard --shell /usr/sbin/nologin wb || true
chown -R wb:wb /opt/whiteboard

# 3. 注册开机自启
cat > /etc/systemd/system/whiteboard.service <<'EOF'
[Unit]
Description=M2Studio Whiteboard Relay
After=network-online.target

[Service]
Type=simple
User=wb
WorkingDirectory=/opt/whiteboard
ExecStart=/usr/bin/node /opt/whiteboard/relay-server.js --port 8787 --dir /opt/whiteboard/rooms --token 你的口令
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now whiteboard
systemctl status whiteboard --no-pager
先临时前台跑一次排查问题也很方便：`node /opt/whiteboard/relay-server.js --port 8787 --token 测试口令`，按 `Ctrl+C` 结束。

四、方案 B：团队全在大陆（最省钱）

流程与方案 A 完全一样，只是购买选项不同：

  1. 腾讯云 → 轻量应用服务器 → 地域选 上海 / 广州 / 北京 / 成都 任一；
  2. 镜像 Ubuntu 24.04；套餐 2核2G 4M（300GB/月），首年活动价约 99 元；若图多，选 2核4G 5M，188 元/年；
  3. 防火墙放行 TCP 8787；
  4. 同样跑 deploy.sh；
  5. 分享 http://IP:8787/?token=口令#room=proj-a。

需要知道的三个差别：

  • 不需要备案，前提是只用 IP:端口 访问；
  • 一旦要绑域名走 443，就必须备案（阿里云/腾讯云控制台都有入口，通常 2–3 周，需要域名已在同一账号实名）；
  • 4M 是峰值带宽，多人同时贴大图会短暂变慢；把图片压到 500KB 以内基本无感。

续费提醒：99 元是首年活动价，原价约 576 元/年；部分"续费同价"档位只允许续一次，请在下单页确认。

五、可选升级：域名 + HTTPS（约 30 分钟）

有域名以后，链接好记，token 也不会以明文在公网传输（现在的 http:// 是明文）。

  1. 买域名：阿里云/腾讯云均可，.com 约 60–85 元/年，.cn 约 30–75 元/年。大陆服务器绑域名需先备案；香港服务器不需要。
  2. 解析：域名控制台加一条 A 记录，主机记录填 wb，值填服务器公网 IP。几分钟后 ping wb.你的域名.com 能看到这个 IP。
  3. 装 Caddy（自动申请并续期免费证书，自动支持 WebSocket）：
    bash apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl gnupg curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list apt-get update && apt-get install -y caddy
  4. 配置：编辑 /etc/caddy/Caddyfile，整个文件写成（把域名和口令换成你的）：
    wb.你的域名.com { reverse_proxy 127.0.0.1:8787 }
    然后 systemctl reload caddy。
  5. 验证：浏览器打开 https://wb.你的域名.com/?token=你的口令，小圆点变蓝即成功。
  6. 之后分享的链接一律用 https://... 开头。页面是 https 时，实时通道会自动用 wss，不需要改任何代码。

证书签不下来，九成是 80/443 没在云厂商防火墙放行，或域名还没解析生效。

六、日常使用规约（3–5 人团队建议）

事项 建议做法
房间怎么分 一个项目一个房间（#room=proj-a），一块白板一个议题；房间号用英文/拼音
白板怎么命名 点顶栏「白板」按钮，「重命名当前」改成 2026Q4-品牌策略 这类能检索的名字
谁在改 点自己头像可以改名换色，协作时光标上会显示是谁
同时编辑 两个人同时拖同一个便签，以最后一次操作为准（后到覆盖）。建议分工区域，或用评论留言协调
异步讨论 按 C 在画布上放评论图钉，可留言、标记「已解决」；没有 @ 提醒，重要结论请当面/群里同步

七、备份、迁移与续费

服务器端备份（推荐每周一次）

# 打包所有房间内容到当前目录
tar czf rooms-$(date +%F).tar.gz -C /opt/whiteboard rooms

# 从你自己的电脑下载（Windows 终端 / macOS 终端，替换 IP）
scp root@你的IP:/root/rooms-2026-11-17.tar.gz .

可以把上面两行写成服务器上的定时任务（每天 3 点备份，保留最近 14 份）：

cat > /etc/cron.d/wb-backup <<'EOF'
0 3 * * * root cd /root && tar czf rooms-$(date +\%F).tar.gz -C /opt/whiteboard rooms && ls -t /root/rooms-*.tar.gz | tail -n +15 | xargs -r rm
EOF

迁移到新服务器（换机、换厂商）

  1. 旧机：tar czf rooms.tar.gz -C /opt/whiteboard rooms，下载；
  2. 新机：按第三节装好环境，把 rooms.tar.gz 传到 /opt/whiteboard/ 并解压 tar xzf rooms.tar.gz；
  3. 重启服务 systemctl restart whiteboard，把新链接发给同事即可。

续费：到期不续费，实例会被释放，rooms 里的内容无法找回。建议开「到期提醒」，并在日历上记一笔；重要内容同时留一份工程文件在网盘。

九、常见故障排查

现象 最可能的原因 怎么办
浏览器一直转圈、打不开 云厂商防火墙没放行 8787 控制台 → 防火墙/安全组 → 加 TCP 8787；curl -I http://IP:8787/health 在本机测
页面能开，但右上角圆点是灰的 WebSocket 没通 看地址是否 http:// 配 ws://；若走了反向代理，确认代理支持 Upgrade；journalctl -u whiteboard -n 50 看有没有 401/断开
提示「该中继已启用口令」 链接里没带 token 用完整链接 ?token=口令#room=xxx（顺序不能反）
连不上且日志有 401 口令不对/少了参数 核对 token；口令含特殊字符时先换成纯字母数字试
两个项目的内容混在一起 房间号用了中文，被并到公共房间 房间号改英文/拼音
同事刷新后图片没了 房间内容超过 --snapmb（默认 12MB）时，服务器既不缓存也不落盘；或他清了浏览器缓存 压缩图片；把服务改成 --snapmb 24；用工程文件补回
服务器重启后内容还在，但新成员看不到 快照没写入磁盘（权限/磁盘满） df -h 看磁盘；ls -l /opt/whiteboard/rooms 看文件；journalctl 看报错
晚上 8–11 点特别卡 跨境线路晚高峰抖动 换香港/大陆节点；或把图片压小、错峰上传大图
手机打开很卡 图片多、板子大 按 Shift+1 适应画布再操作；图片先压缩
改了端口后打不开 防火墙只放行了旧端口 放行新端口，并且通知所有人换新链接
服务没起来 端口被占用 / Node 版本过低 journalctl -u whiteboard -n 50；node -v 是否 ≥18
装不上 Node（卡在下载） 官方源慢 换淘宝镜像：export NODEJS_ORG_MIRROR=https://npmmirror.com/mirrors/node 后重跑；或直接 apt install nodejs 用系统自带 18

服务器上的三条保命命令：

systemctl status whiteboard --no-pager     # 服务活着吗
journalctl -u whiteboard -n 50 --no-pager  # 最近 50 行日志
curl -s http://127.0.0.1:8787/health       # 本机自测（排除网络问题）

十、安全检查清单

长期对外开着，至少做到这六条：

  • [ ] 设置了 --token，口令 12 位以上、不含姓名/项目名；
  • [ ] 口令只发给团队，不贴在公开群公告、不写进对外文档；
  • [ ] 定期 apt-get update && apt-get upgrade -y（每月一次）；
  • [ ] root 密码强口令，不用 123456；能上密钥登录更好；
  • [ ] 有条件就上 HTTPS（第五节），否则 token 在公网是明文；
  • [ ] 云账号开启二次验证，避免账号被盗后服务器被清空。

关于权限，需要说明清楚：这套白板只有"房间口令"，没有账号与权限体系——拿到链接的人都能编辑，也无法审计"谁改的"。3–5 人的信任团队没问题；如果要给外部客户看，建议单独开一个房间、只发只读需求给他们截图/导出的 PDF。

附录 B · 中继参数

参数 默认 作用
