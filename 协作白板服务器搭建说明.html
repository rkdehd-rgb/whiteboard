协作白板服务器搭建说明

零基础可照做 · 局域网多人实时协作 · 内容自动保存在本机
M²Studio 协作白板 · 长期团队协作部署

面向零基础用户。照着做即可，不需要懂编程。
做完以后：一台电脑开着，同一 Wi-Fi 下的同事或手机打开一个网址，就能一起在一块白板上画便签、连线、贴图；内容自动存在这台电脑上，关机重启后还在。

零、你需要什么

项目 说明
一台常开的电脑 Windows / macOS / Linux 都行，做"服务器"用
Node.js 免费，运行时环境，装一次就行
三个文件 whiteboard.html、relay-server.js、启动中继.bat

把这三个文件放在同一个文件夹里，例如 D:\白板\。这是整个过程中唯一需要注意的"文件管理"要求——放一起，别分开。

一、安装 Node.js（只需做一次）

  1. 打开官网 https://nodejs.org，点左边那个绿色的 LTS（长期支持版）下载。
  2. 双击安装包，一路点"下一步"，全部用默认选项即可。
  3. 装完后重启一次电脑（重要，否则命令行可能找不到 node）。
  4. 验证是否装好：
    - 按 Win + R，输入 cmd，回车，弹出黑色窗口；
    - 输入 node -v 后回车；
    - 显示类似 v22.22.2 就是装好了。若提示"不是内部或外部命令"，说明没装好或没重启，回到第 1 步重来。

二、启动服务器

  1. 双击 启动中继.bat。
  2. 会弹出一个黑色窗口，显示类似下面的内容：

```
白板服务器已启动，别关这个黑窗口。

 自己用:   http://localhost:8787
 同一 Wi-Fi 的同事/手机用: http://192.168.31.8:8787

 房间内容保存在: D:\白板\rooms

```

  1. 这个黑窗口不能关。关掉就等于服务器关掉，别人就进不来了。最小化可以。
  2. 如果 Windows 弹出"是否允许此应用访问网络"的防火墙提示，点允许访问（至少需要勾选"专用网络"）。不让通行的话，别人连不上。
  3. 记下窗口里那行 http://192.168.31.8:8787——这就是给别人用的网址（你机器上的数字会不一样，以你看到的为准）。

若窗口一闪就没了，或提示端口被占用：见文末"常见问题"第 2、3 条。

三、自己先打开看看

浏览器地址栏输入 http://localhost:8787（或者黑窗口里那行"自己用"的地址），回车。

你会看到白板界面。此时：

  • 右上角"协作"按钮旁的小圆点是蓝色的，说明已经自动连上了服务器（灰色=没连上）；
  • 左上角会显示当前白板名称，默认是公共白板；
  • 第一次进来是空的，双击画布就能加便签。

试着加两个便签、画两笔，确认能正常操作。

四、让别人加入

把第二步记下的那个网址发给同事，例如 http://192.168.31.8:8787。他们：

  • 电脑：浏览器打开这个网址；
  • 手机：连同一个 Wi-Fi，手机浏览器打开这个网址（手机也能画）。

所有人默认都落在"公共白板"这一块，改动是实时的：你拖动便签，对方屏幕上一秒内就会跟着动。

五、开多块独立白板

默认情况下，所有不带房间号的访问者都在同一块"公共白板"上。想让不同项目各自独立，就在网址后面加 #room=房间名：

http://192.168.31.8:8787/#room=产品评审
http://192.168.31.8:8787/#room=周会

房间号只能用字母、数字、下划线、点、横线（1–64 个字符），建议写英文或拼音，例如 #room=a1。中文房间号会被中继归到公共房间，导致不同项目的内容混在一起。把这个带 #room= 的完整网址发给对应的人，他们就会进到各自的房间，互相看不到、互不干扰。

房间名就是房间的身份标识，别泄露给不相干的人——这个白板没有密码。

六、日常怎么用

想做的事 怎么做
保存 不用手动保存。每次改动约 0.5 秒内自动存；按 Ctrl + S 可立刻存一次
白板改名 / 新建 / 删除 / 覆盖 点顶栏的"白板"按钮（或 Ctrl + B）打开存档面板
导出图片或 PDF Ctrl + E，选"导出图片 PNG"或"导出 PDF 文档"
插入图片 按 I 或点工具栏图片图标，也可直接把图片拖进画布
换端口 右键 启动中继.bat → 编辑，把里面的 8787 改成别的数字（如 9000），保存后重新双击

存档面板里的三种操作要分清：

  • 打开：切换到那块白板（当前内容会先自动保存）；
  • 覆盖：用当前画面替换那块白板的内容（会二次确认，替换后不可撤销）；
  • 删除：删掉那块白板（会二次确认；删的是当前这块时，会自动帮你切到另一块）。

七、内容存在哪里

内容双份保存，各有分工：

位置 作用 特点
服务器目录 rooms\房间名.json 房间的最新完整快照 换设备、换浏览器都能拿到；服务器重启后自动加载
每台设备浏览器本地 本地存档列表（可离线编辑） 清浏览器缓存会丢；适合单机整理

所以：

  • 备份：把服务器上的 rooms 文件夹整个拷走即可，里面是每个房间一个 .json 文件。
  • 迁移：把 rooms 文件夹拷到新机器的同一位置，双击启动，内容就回来了。
  • 想清空重来：关掉服务器，删掉 rooms 文件夹里对应的 .json，再启动。

注意：快照是"每个房间最后一份完整内容"，不是版本历史——没有"回到 10 分钟前"这种功能，重要节点请用导出 PDF 留档。

八、常见问题排查

1. 双击 bat 后黑窗口一闪而过，或提示"node 不是内部或外部命令"
Node.js 没装好，或装完没重启。回到第一步重装并重启电脑。

2. 黑窗口里出现 EADDRINUSE 或"端口被占用"
8787 端口已被别的程序占用。编辑 启动中继.bat 把 8787 改成 9000（或别的数字）再启动，网址里的端口也要跟着改。

3. 别人打不开网址
按顺序排查：
- 双方是否在同一个 Wi-Fi（公司网络常常把设备互相隔离，这种情况改用手机热点）；
- 服务器那台电脑的防火墙是否放行了 Node.js（第二步第 4 点）；
- 网址里的 IP 是不是黑窗口里显示的那个（本机 IP 可能变化，以窗口显示为准）；
- 服务器黑窗口是不是被关掉了。

4. 页面能打开，但小圆点是灰的，提示"中继连接失败"
说明网址能通、但实时通道没连上。检查：
- 若是手动填地址，必须是 ws:// 开头（不是 http://），格式 ws://192.168.31.8:8787；
- 从服务器网址打开时会自动填好，一般不需要手填；
- 若页面是 https:// 开头的（例如放到公网），地址必须改成 wss:// 开头，否则浏览器会拦截。

5. 画了内容，第二天打开没了
- 服务器当时是否开着（只有开着才会收到并保存同步）；
- 看服务器目录 rooms 里有没有对应的 .json 文件，有的话内容就在；
- 存档面板里换一下白板看看，可能只是在另一块白板上。

6. 手机能打开但操作很卡
图片太多太大时会卡。尽量用压缩过的图片，单张控制在几百 KB。

九、进阶：让外网的人也能用（可选）

需要长期给跨地区团队用、想知道买哪台云服务器、怎么配置域名与备份，见同目录的
《团队长期协作部署指南》（团队长期协作部署指南.md/.pdf），那份写得更细，也包含一键部署脚本。

上面全部是局域网方案，只在同一个 Wi-Fi 下有效。想让外地同事访问，需要一台有公网 IP 的云服务器，并配置 HTTPS：

  1. 买一台云服务器（各家云厂商的最低配就够），装好 Node.js；
  2. 把 whiteboard.html、relay-server.js 传到服务器同一目录，用 node relay-server.js --port 8787 启动；
  3. 装 Nginx，把 443 端口反代到本机的 8787，并用 Let's Encrypt 申请免费证书；
  4. 云服务器的安全组/防火墙放行 443 端口；
  5. 用 https://你的域名 打开白板即可——程序会自动识别 https 页面并使用 wss:// 连接。

关键区别只有一句：页面是 https 时，实时通道必须是 wss，不能是 ws，否则浏览器按"混合内容"直接拦截。

十、不用 bat，直接用命令行（可选）

在三个文件所在的文件夹里打开命令行，执行：

node relay-server.js                        # 默认 8787 端口
node relay-server.js --port 9000            # 指定端口
node relay-server.js --dir D:\白板\rooms    # 指定快照目录
node relay-server.js --no-save              # 只做实时转发，不落盘
node relay-server.js --token 你的口令        # 开启访问口令（也可用环境变量 RELAY_TOKEN）
node relay-server.js --maxconn 200          # 连接数上限（默认 500）
node relay-server.js --ratemsg 60           # 单连接每秒消息上限（默认 120）
node relay-server.js --snaprooms 100        # 内存中保留多少个房间快照（默认 200，LRU 淘汰）
node relay-server.js --snapmb 8             # 单房间快照体积上限，单位 MB（默认 12）

### 开启访问口令后怎么用

口令只决定「谁可以连上中继」，不影响页面本身：

http://<服务器IP>:8787/?token=你的口令


页面会自动把网址里的查询串带到 WebSocket 连接上。**口令不对的连接会被拒绝（401）**，
没带 token 的访客会看到「该中继已启用口令」的提示，而不是静默失败。

> 口令是明文比对、ws:// 不加密。局域网用没问题；放到公网请走 `wss://`（反向代理上开 TLS）。

浏览器打开 http://localhost:8787/health 可以看到当前的房间和在线人数，用来确认服务器是否正常工作。

需要记住的三句话

  1. 黑窗口别关，关了别人就进不来。
  2. 内容在 rooms 文件夹，备份就拷这个文件夹。
  3. 网址后面加 #room=名字 就能开出互不相干的独立白板。
